How about RAMADR /INCADR/READ.

For example, to retreive some registers

       <scratch adr> => MEMADR /READ
       MEMDATA /INCADR => GPREG #20
       MEMDATA /INCADR => GPREG #21
       MEMDATA /INCADR => GPREG #22

might be faster if we had:

       <scratch adr> => MEMADR /READ
       MEMDATA /INCADR/READ => GPREG #20
       MEMDATA /INCADR/READ => GPREG #21
       MEMDATA /INCADR/READ => GPREG #22

This would only be faster if /INCADR causes no wait, ie, can run as fast as the WIZ cycle. Otherwise, if it's not done, there is no advantage in also pre-starting the read. Well, ok, there could be a little if other instructions were interleaved between the MEMDATA references, ie,

MEMDATA /INCADR/READ => XXX
<any other instruction>
MEMDATA => YYY
In this case, the MEMDATA would be avail faster then if /INCADR/READ wasn't an option. My guess is that this is rare, as the point of /INCADR is to read sequential addresses, and one probably often wants them right in a row.

But if we can build an incrementer (by 4) faster than the WIZ cycle (I don't believe we can!) then /INCADR/READ would always be useful.

Note that you wouldn't want to auto imply /read on a read of memdata/incadr. For instance, to add one to several sequential items:

<scratch adr> => MEMADR /READ
MEMDATA => FB1REG # counter            ! read memdata
FB1REG # counter => MEMDATA /INCADR    ! write back same data +1

MEMDATA => FB1REG # counter            ! read next memdata
FB1REG # counter => MEMDATA /INCADR    ! write back same data +1
etc...


So the question is, can we build a MEMADR incrementer faster than the WIZ main transfer cycle?
