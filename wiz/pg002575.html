The MEMXID /STACK register

We have defined the MEM registers which, so far, only allow access to bytes within the executing memory. Now we will describe access BETWEEN memories in the Central Memory device.

A WIZ could be thought of as having multiple RAM memories, each from 0 to 232-1 bytes. Each memory can be independently loaded and executed, and any number (more than 232) can coexist.

A memory may contain executable code, and may be "called" as any subroutine may be called. To do this, the MEMXID /STACK register is used. It is just like the RAMXADR /STACK and MEMXADR /STACK, but whereas these use a 32 bit address or offset, the MEMXID /STACK register requires a <<memory id>> which can be much longer than 32 bits.

In order to easily address a <<memory id>> from a 32 bit register, a packet of information must be created, called a "memory id descriptor packet". This packet contains several items, including the variable length <<memory id>> of the memory to be accessed. It is stored somewhere within the current memory, and referred to by its <offset>, which IS a 32 bit (or less) quantity.

One writes to the new register, MEMXID /STACK, the 32 bit relative address within the current memory of a memory id packet. This causes the next WIZ instruction byte to come from the first byte of that memory (after pushing the current memory id and offset onto the stack).

Thus:

<offset of memory id packet>  =>  MEMXID /STACK
   .
   .
   .
packet: several bytes, <<memory id>>, etc
causes a "call subroutine" to the referenced memory from the Central Memory bank.
