In summation:

We have defined a simple memory architecture:

  • Software deals only with a single simple memory architecture:
    • the CENTRAL MEMORY BANK
    • which contains MEMORIES
    • accessed by MEMORY ID
    • and having internal 32 bit addressing by OFFSETS.
  • Software knows nothing of DISK, RAM, CACHE, VIRTUAL MEMORY, etc.
  • We define a set of registers, MEMDATA, MEMADR, MEMXADR, MEMXID, etc, which parallel all the RAM registers but cause software interrupts to a handler instead.
  • We use the technique of the fixup to accomplish something like run-time-binding, to translate the software memory references into actual RAM memory references, which then execute at the maximum speed the hardware can muster (ie, truely zero overhead).
  • We manage the memory with software algorithms to move common code to faster hardware and uncommon code to slower hardware, thus increasing efficiency still further.
  • We thus TAKE COMPLETE SOFTWARE CONTROL OF THE MEMORY SUBSYSTEM.


We have completely isolated the actual memory hardware, the Central Memory -- which has YET to be described! -- from the software. With no extra hardware, the WIZ gains a sophisticated memory subsystem while remaining an incredibly simple ISC computer! We have defined a machine having all the efficiencies associated with level one cache, level two cache, content addressable page maps, virtual memory hardware, and various hardware addressing modes, etc, yet with absolutely none of the hardware complexity.

We can thus focus all hardware development efforts on speeding up a simple set of things, rather than constantly trying to add complexities to it.

And by TAKING COMPLETE SOFTWARE CONTROL OF THE MEMORY SUBSYSTEM we create a situation where many new things are possible. Advanced uses of the fixup have yet to be explored.
