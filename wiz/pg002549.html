The Network Cache

Suppose WIZ A is connected to the central memory through WIZ B. Suppose WIZ A requests memory <<M>> from the central memory. This request will go to WIZ B first. WIZ B either already has <<M>> in its own cache, or it will go out to its central memory connection and get it. When it gets it, it puts it into its own cache. It then transmits its copy of <<M>> back to WIZ A to complete the cycle. At this point, both WIZ A and WIZ B have a copy of the memory <<M>> in their caches.

In general, every WIZ between the central memory and WIZ A will have a copy of <<M>> in its cache, at least at the time of the initial transfer.

THUS, AT EVERY POINT ON THE  WIZ CENTRAL MEMORY BANK "NETWORK", DATA IS BEING LOCALLY CACHED. This is very different from today's Internet, on which data hops from point to point and is not saved anywhere along the way.

If WIZ A has a very much smaller cache than WIZ B, it may occur that memory <<M>> gets deleted from WIZ A's cache before it is deleted from WIZ B's cache. Should WIZ A need memory <<M>> again, its memory handler will send a request to WIZ B again. WIZ B, still having memory <<M>> in its cache, can then send a copy to WIZ A again, this time WITHOUT HAVING TO GO TO THE CENTRAL MEMORY BANK.

And if another WIZ, WIZ C, were also connected to WIZ B, and WIZ C also needed the same memory <<M>>, and also requested it from WIZ B, then again, WIZ C's request would be satisfied by WIZ B WITHOUT HAVING TO GO TO THE CENTRAL MEMORY BANK.

Suppose we take dozens of little WIZes with tiny caches and connect them with WIZ-to-WIZ comm lines to a single large WIZ with a large cache (eg, disk). Whenever one of the little WIZes needs a memory it will go to the large WIZ with a request for it. And if each of these small WIZes uses the same program or database, at least some of the time, then the first time one of them accesses it the large WIZ would get it from the central memory, but from there on out it would supply the program or data to all of the little WIZes over and over again without generating any traffic to the central memory.

This large-cached WIZ is then something of a "local server" supporting a bunch of  small WIZes. Yet there is no special "server software" or "network software" or "operating system" supporting this, no special "configuration" required for it. There is just the memory handler software as we have already discussed.

As always, simplicity is our keynote!
