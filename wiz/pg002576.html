Nomenclature:

I will use the notation <xx> to represent any 8 bit byte, <xx,xx> to represent two bytes, and <xx,xx,xx> and <xx,xx,xx,xx> to represent any three or four bytes.

Numbers ending in "H" will indicate hexadecimal numbers. Eg, <61H>.
Numbers ending in "B" will indicate binary numbers. Eg, <01100001B> = <61H>.

I will use the symbol "<... any phrase ...>" to mean any number up to 232-1, described by the contained phrase and its context. The symbol therefore refers to 1, 2, 3, or 4 bytes - the exact number is implied by the value described. Eg, <123456H> = <12H,34H,56H>.

I will use the symbols RAMDATA, RAMDATA /INCADR, STACK, FBREG, FBREG /SAME, FBREG /0, FBREG /1, CONST /0B, CONST /1B, CONST /2B, CONST /3B, CONST /4B, SKIPIF /NONZERO, SKIPIF /ZERO, RAMADR, RAMADR /READ, RAMADR /ADDER, RAMXADR, and RAMXADR /STACK to represent the numbers 0 through 15 as given in the WIZ Register Definitions table.

The above defines the entire mnemonic set for all internal WIZ registers. All instructions are merely a pair of these registers. I will write instructions as a pair of registers, source first, destination second, separated by the symbol "=>", like this:

STACK => RAMDATA
which means copy the STACK register to the RAMDATA register.

I may also sometimes use the symbol "<=" and write the destination first and source second. Thus:

RAMDATA <= STACK
is identical to STACK => RAMDATA.

Also, when copying a constant with the CONST registers, I will generally leave out the CONST register itself and just write the constant (the chapter following on CONST will give more detail on this). For example, the instruction which writes the three byte constant <123456H> to the stack is:

CONST /3B => STACK , <123456H>
But I will usually write this instead:
<123456H> => STACK
