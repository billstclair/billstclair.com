RAMXADR/00000 and THREAD MODE:

By setting a status register flag called "thread mode" to one, the WIZ cycle changes. Instead of the RAMXADR logic bringing a program byte in as 4 bits of source and 4 bits of destination, it locks into a continuous CONST /1B => RAMXADR /00000. That is, each byte it brings in is sent to RAMXADR /00000 without any other decode.

After executing this call to a low memory subroutine, the WIZ goes to normal mode during the execution of that subroutine, and then returns to thread mode upon return, where the next single byte is fetched and sent to RAMXADR/00000. In thread mode, execution of a 00 byte terminates thread mode.

For example, suppose you have 5 subroutines in a row to call, A, B, C, D, and E, and all are located in low memory at multiples of 32 word boundaries. Instead of:

    <A> => RAMXADR/00000
    <B> => RAMXADR/00000
    <C> => RAMXADR/00000
    <D> => RAMXADR/00000
    <E> => RAMXADR/00000

which takes two bytes each (<CONST /1B => RAMXADR /00000>, <nn>), we can use thread mode to have:

    <ENTER THREAD MODE>, <A>, <B>, <C>, <D>, <E>, <00>

In thread mode we use just one byte per subroutine call, plus a few of overhead to enter thread mode and one more to exit it.

Also note that a subroutine can use the return stack pointer to grab in-line arguments and modify the pointer to return past the arguments. Thus, if subroutine B takes two bytes of data, and E takes 3, we would have:

    <ENTER THREAD MODE>, <A>, <B,xx,xx>, <C>, <D>, <E,xx,xx,xx>, <00>

If we think of some other (traditional) processor's "instruction set" as a set of 256 or less subroutines which can be emulated or implemented on the WIZ, then a WIZ running in "thread mode" basically BECOMES that other processor.

Note also that this lower memory is likely to be very fast memory (discussed later, low memory is on the WIZ chip itself), and so this "microcode" can execute very fast.

Operating in this mode, the WIZ is basically indistinguishable from a downloaded microcoded version of that other processor. In which case it has become a CISC. Far out, huh?

I'm not totally certain we need to include thread mode into the machine. It's a cool idea, and adds very little extra hardware, but it does add some extra hardware and it could slow the main instruction loop down. We'll see...
