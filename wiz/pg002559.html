The MEM registers in Function Block #1

The interface to the Central Memory is accomplished thru standard function block #1, already defined to have the basic logical and arithmetic functions for all WIZes.

A set of 8 registers, almost identical in function to the RAM registers, is defined in FB1 as follows:
 
MEMDATA Like RAMDATA
MEMDATA /INCADR Like RAMDATA /INCADR
MEMADR Like RAMADR
MEMADR /READ Like RAMADR /READ
MEMADR /ADDER Like RAMADR /ADDER
MEMXADR Like RAMXADR
MEMXADR /STACK Like RAMXADR /STACK
MEMXID /STACK New: for inter-memory call
MEMFB2 New: for inter-memory call

When a memory in the Central Memory executes, it can load from, store into, jump to or call any of its own bytes, but is restricted in ability to load, store, jump to or call bytes in any other memory. All of its memory references are to offsets within itself only.

Thus, while the RAM registers -- RAMADR, RAMDATA, and RAMXADR -- all hold 32 bit absolute addresses in the RAM, the MEM registers -- MEMADR, MEMDATA, and MEMXADR -- all hold 32 bit offsets within the currently executing memory.

Thus, the branch instruction, which used to look like this:

<absolute address in RAM of destination>  =>  RAMXADR
is now changed to this:
<relative offset in the current memory of destination>  =>  MEMXADR
Note that as MEMXADR is a register in FB1, the above notation is actually a shorthand for:
<relative offset in the current memory of destination>  =>  FB1 REG# <MEMXADR>
I will continue to use the more direct notation.

Loading and storing operations, those operations which use the MEMADR and MEMDATA registers, may now occur only to data within the same memory as is currently executing . Thus, what used to look like this:

<1234H>  =>  RAMADR
<0>      =>  RAMDATA
which stored a zero into absolute RAM location 1234H, is now changed to this:
<1234H>  =>  MEMADR
<0>      =>  MEMDATA
which stores a zero into relative byte number 1234H within the executing memory.

As before, /READ and /INCADR are both applicable. Thus, to load a series of bytes within a memory:

<offset of data>  =>  MEMADR /READ
GPREG #34  <= MEMDATA /INCADR
GPREG #35  <= MEMDATA
Likewise, MEMADR /ADDER works like RAMADR /ADDER. Thus, to address A[i], where A is an array of bytes within the current memory, and i = GPREG 16, we have:
<offset of array A> => MEMADR
GPREG # 16 => MEMADR /ADDER
A subroutine may be contained within a memory, and called like this:
<offset of subroutine> => MEMXADR /STACK
And the subroutine can return with:
STACK => MEMXADR
Thus, all the RAM registers:
RAMDATA, RAMDATA /INCADR, RAMADR, RAMADR /READ, RAMADR /ADDER, RAMXADR, RAMXADR /STACK
are paralleled with MEM registers in FB1:
MEMDATA, MEMDATA /INCADR, MEMADR, MEMADR /READ, MEMADR /ADDER, MEMXADR, MEMXADR /STACK
These work essentially identically except to use relative offsets within the current memory instead of absolute addresses within the entire RAM.
